# Auto Answer AI

悬浮式在线答题辅助浏览器扩展，面向**学习通（chaoxing.com）**与**智慧树（zhihuishu.com）**的作业 / 考试页面。

它把你当前页面上的题目解析出来，交给你自己配置的大模型（任意 OpenAI 兼容接口）作答，再自动填涂到页面上；全部题目填写成功后，可以选择自动交卷。

> **使用范围**：本工具只做页面 DOM 读取、答案填写与可选的交卷点击，**不破解、不绕过平台校验**。请仅用于自测、练习或已获得授权的场景，并遵守所在学校 / 机构的规定。
>
> **暂不支持刷课**：本扩展不处理视频播放、章节进度、签到、讨论、自动登录等内容，详见[第 2 节](#2-功能边界做什么与不做什么)。

## 1. 项目需求与定位

在线作业 / 考试里大量题目是机械的「读题 → 选择 → 下一题」，本项目的目标是：

1. **识别题目**：在页面 DOM 中定位题干、选项、填空框、图片；
2. **生成答案**：把题目整理成结构化 JSON，调用用户自己配置的大模型；
3. **自动填涂**：用原生事件模拟的方式点击选项 / 写入输入框，兼容 Vue / React 受控组件；
4. **可选交卷**：仅在**全部题目都填写成功**时，才允许触发平台的交卷流程。

需求概览：

| 维度 | 要求 |
| --- | --- |
| 输入 | 学习通 / 智慧树的练习、作业、考试页面 DOM，包含多层 iframe 与图片 |
| 输出 | 在页面上自动选中选项、写入填空 / 简答，可选触发交卷 |
| 模型 | 任意 OpenAI Chat Completions 兼容接口，文本与视觉模型可分开配置 |
| 安全 | 无内置 Key；未答完或有失败时绝不交卷；不绕过平台警告与校验 |
| 兼容 | Chrome / Edge 111+，Manifest V3，样式与宿主页面隔离 |
| 可维护 | 策略模式拆分平台选择器，页面改版时只改对应策略文件 |
| 可观测 | 悬浮面板提供实时日志、逐题结果、已填 / 跳过 / 失败统计 |

设计原则：

- **不带任何内置 Key**：模型地址、Key、模型名全部由用户填写，保存在本地。
- **请求只从 Background 发出**：避免页面 CORS 限制，也避免把 Key 暴露给页面脚本。
- **答案由模型生成，可能出错**：扩展不会替你判断对错，交卷前请自行检查。
- **安全优先**：未答完、有跳过 / 失败、平台弹出「还有 N 题未作答」时，绝不自动提交。

## 2. 功能边界：做什么与不做什么

### ✅ 做什么

| 能力 | 说明 |
| --- | --- |
| 题目解析 | 学习通练习页 / 作业考试页，智慧树新版作业页（含一页一题、组合题） |
| 多层 iframe | 支持「顶层 → cards.html → work.html」两层及以上嵌套，跨域 iframe 同样可用 |
| 题型覆盖 | 单选、多选、判断、填空、简答、组合题 |
| 图片题 | 题干 / 选项图片收集、压缩、缓存；OCR 转文字或视觉模型直接作答 |
| 自动填涂 | 选项点击、输入框写入、UEditor 编辑器写入、原生事件模拟 |
| 可选交卷 | 全部填写成功后才允许，带二次确认和平台警告拦截 |
| 实时日志 | 平台识别、题目数量、模型返回、逐题填涂结果、失败原因 |
| 多模型 | 任意 OpenAI 兼容接口；文本模型与视觉模型可分开配置 |

### ❌ 不做什么（明确不支持）

| 不支持 | 说明 |
| --- | --- |
| **刷课 / 刷进度** | 不自动播放视频、不静音 / 倍速、不改写章节进度、不做章节测验批量刷题 |
| **签到 / 讨论 / 通知** | 不处理签到、讨论区、投票、问卷等非答题页面 |
| **自动登录** | 需要用户自己登录平台 |
| **破解验证码** | 不识别 / 绕过图形验证码、滑块、人脸识别 |
| **绕过监考** | 不规避切屏检测、摄像头监考、考试锁屏等机制 |
| **伪造提交结果** | 不修改平台提交接口或伪造分数，只做页面上的正常点击 |
| **其他平台** | 目前仅适配学习通与智慧树；其他站点不会注入面板 |
| **只解析不填写** | 暂未提供「预览答案但不填涂」模式 |

## 4. 支持的题型与答案格式

### 支持的题型

| 题型 | 填涂方式 |
| --- | --- |
| 单选题 | 点击对应选项 |
| 多选题 | 依次点击多个选项 |
| 判断题 | 点击「对 / 错」（映射到 A / B 或平台对应的值） |
| 填空题 | 写入 `input` / `textarea`；学习通 UEditor 通过主世界 API 写入 |
| 简答题 | 写入 `textarea` / 富文本编辑器 |
| 组合题 | 父题干作为背景，子题单独作答（智慧树） |

### 模型输出格式

扩展通过 Prompt 要求模型**只返回 JSON 数组**：

```json
[
  { "id": "0", "type": "单选", "answer": "A" },
  { "id": "1", "type": "多选", "answer": "A,C" },
  { "id": "2", "type": "判断", "answer": "对" },
  { "id": "3", "type": "填空", "answer": "答案1|答案2" }
]
```

- 单选：一个选项字母，如 `"A"`
- 多选：逗号分隔，如 `"A,C"`，也接受 `["A","C"]`
- 判断：`"对"` / `"错"`，也接受 `"A"` / `"B"`
- 填空 / 简答：纯文本；多个空位用 `|` 分隔
- 答案解析器容忍：Markdown 代码块、前后解释文字、`{ "answers": [...] }` 包裹、`{ id: answer }` 映射

### 图片格式

- 支持 `png` / `jpeg` / `webp` / `gif`
- 图片在页面内收集后用 canvas 压缩为 JPEG（最长边 1600px）
- 单题最多 4 张，单次请求最多 8 张
- 同源图片直接抓取；跨域 / 无 CORS 头的图片由 Background 代理抓取

## 5. 支持的大模型接口

### 接口协议

只支持 **OpenAI Chat Completions 兼容接口**（`POST /chat/completions`），不要求流式输出。

Base URL 填法（自动归一化）：

| 填写方式 | 实际请求地址 |
| --- | --- |
| `https://api.deepseek.com/v1` | `https://api.deepseek.com/v1/chat/completions` |
| `https://api.deepseek.com`（只有域名） | `https://api.deepseek.com/v1/chat/completions` |
| `https://xxx/v1/chat/completions`（完整地址） | 原样使用 |

- 请求超时：60 秒
- 认证方式：`Authorization: Bearer <API Key>`
- 非 2xx、超时、返回格式异常都会在面板日志中给出明确提示

### 视觉服务

图片识别使用的视觉服务可以**独立配置**，每一项留空都会回退到主模型配置：

| 配置项 | 留空时 |
| --- | --- |
| 视觉 Base URL | 使用主 Base URL |
| 视觉 API Key | 使用主 API Key |
| 视觉模型 | 使用主模型 |

内置预设（只填充地址与模型名，Key 需自己填写）：

| 预设 | Base URL | 模型 |
| --- | --- | --- |
| 智谱免费视觉 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4.1v-thinking-flash` |
| Gemini | `https://generativelanguage.googleapis.com/v1beta/openai` | `gemini-2.5-flash` |
| Qwen / DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-plus` |
| 本地 Ollama | `http://localhost:11434/v1` | `qwen2.5-vl:7b` |

### 两种图片处理方式

| 模式 | 流程 | 适用场景 |
| --- | --- | --- |
| 图片转文字（OCR，默认） | 视觉模型先逐张转写 → 文字拼进题干 → 主模型答题 | 免费视觉额度 + 便宜文本模型 |
| 视觉模型直接作答 | 图片随题目一起发给视觉模型 | 视觉模型强、题量不大 |

- OCR 结果按图片 hash 缓存在内存中，刷新页面后清空
- 免费视觉服务限流（如智谱 `1302` / `1305`）会自动退避重试，仍失败则本轮跳过该图
- 主模型不支持视觉输入时，会自动去掉图片重试，并在日志中提示

| 浏览器 | 支持情况 |
| --- | --- |
| Google Chrome | ✅ **111 及以上**（推荐最新稳定版） |

## 7. 安装

### 环境要求

- Node.js `^20.19.0` 或 `>=22.12.0`（Vite 8 要求）
- npm 10+
- Chrome / Edge 111+

### 构建

```bash
npm install
npm run build      # 类型检查 + 生产构建，产物在 dist/
```

开发模式（CRXJS 提供 HMR）：

```bash
npm run dev        # 产物同样输出到 dist/
```

### 加载扩展

1. 打开 `chrome://extensions/`（Edge 为 `edge://extensions/`）
2. 打开右上角「开发者模式」
3. 点击「加载已解压的扩展程序」
4. 选择本项目的 `dist/` 目录
5. 打开学习通或智慧树的答题页面，右下角出现悬浮面板

> 修改代码后：生产构建需要重新执行 `npm run build`，然后在扩展页点击刷新，并**刷新答题页面**。

## 8. 使用说明

面板分为「设置」和「控制台」两个 Tab，右下角可折叠。

### 「设置」Tab

| 字段 | 说明 |
| --- | --- |
| Base URL | OpenAI 兼容接口地址，默认 `https://api.deepseek.com/v1` |
| API Key | **只写不读**：已保存的 Key 不回显，输入新 Key 后点「保存设置」；请求由 Background 以 `Bearer` 方式发送 |
| 模型 | 例如 `deepseek-chat`、`gpt-4o-mini`、`qwen-plus` |
| 自动交卷 | 默认关闭。开启后仅在**全部题目填写成功**时弹确认框 |
| 图片识别 | 默认关闭。开启后可选择 OCR 或视觉模型直接作答 |
| 图片处理方式 | `图片转文字` / `视觉模型直接作答` |
| 视觉 Base URL / Key / 模型 | 可选，逐项留空回退主模型 |
| 视觉预设 | 智谱 / Gemini / Qwen / Ollama，一键填充地址与模型 |
| 测试识图 | 生成一张本地测试图，验证视觉服务是否可用 |
| 测试连接 | 用当前主模型发一次最小请求，验证地址 / Key / 模型 |
| 保存设置 | 保存到本地，刷新页面后自动回填 |

### 「控制台」Tab

- **启动答题**：开始解析并填涂
- **停止答题**：运行中可随时停止；当前在途请求结束后不再继续，也不会交卷
- **实时日志**：平台识别、题目数量、模型返回条数、逐题结果、失败原因
- **进度统计**：已填 / 此前已答 / 跳过 / 失败

普通页面（一次性批量）：

1. 解析当前页面与所有子 iframe 的题目
2. 汇总后一次性请求模型
3. 按 frame 路由填涂
4. 统计结果

智慧树一页一题（分页）：

1. 自动点击答题卡回到第一题
2. 每题：解析 → 请求 → 填涂 → 点击「下一题」
3. 只有确认到达最后一项才结束；切换失败立即停止，**不交卷**

## 9. 典型使用流程

### 学习通作业 / 考试

1. 登录学习通，打开作业页面，等待题目和编辑器加载完成
2. 点击右下角面板 →「设置」→ 填 Base URL / Key / 模型 →「保存设置」→ 可先「测试连接」
3. 切到「控制台」→「启动答题」
4. 观察日志：应出现「iframe 中解析到 N 道题」以及逐题「已填」
5. 检查页面填涂结果
6. 如需自动交卷：提前打开「自动交卷」；扩展会在全部填写成功后弹出确认框
7. 也可手动点击页面上的「提交」按钮

### 智慧树新版作业

1. 打开作业页，确认答题卡和题目已加载
2. 配置模型并保存
3. 启动答题，扩展会自动回到第一题并逐题处理
4. 日志出现「答题完成：已填 N · 跳过 0 · 失败 0」后再考虑交卷

> 如果日志出现「答题未完成」「已跳过自动交卷」，说明有题目没填上或模型没返回答案，请手动处理后再提交。

## 10. 自动交卷与安全闸门

自动交卷**默认关闭**。开启后必须同时满足：

```text
已填 + 此前已答 === 总题数
跳过 === 0
失败 === 0
```

> 智慧树分页页从第一道未答题开始，「此前已答」由答题卡状态统计；普通页面该值恒为 0。

才会：

1. 弹出扩展自己的确认框（`已填写 N/N 道题，确定现在交卷吗？`）
2. 用户确认后，点击顶层或对应 iframe 内的交卷按钮
3. 平台若再弹确认框，只确认普通提交

以下情况**绝不自动提交**：

- 有题目未识别、未填写、填写失败
- 智慧树分页切换失败
- 平台弹窗包含「未作答 / 未完成 / 还有 N 题 / 漏做」
- 找不到交卷按钮

学习通作业页的提交会先等待页面的 `validate` 请求完成（最多 6 秒），再判断确认框内容；平台警告会回传到控制台日志。

## 11. 常见问题

### 提示「未识别到题目」

按顺序检查：

1. **是否刷新了页面**：安装 / 更新扩展后，旧 iframe 不会自动注入，需要刷新整个答题页
2. **是否在支持的页面**：域名必须是 `*.chaoxing.com` 或 `*.zhihuishu.com`
3. **题目是否在 iframe 里**：等待内层页面加载完成再点「启动答题」；扩展会在零结果时自动重试一次
4. **页面结构是否改版**：把该页面的 HTML 保存后反馈，选择器集中在 `src/content/strategies/` 中修改

### 识别到了题目，但页面没有选中 / 没有写入

- 可能是页面改版导致选择器失效
- 学习通填空依赖 UEditor：请确认编辑器已加载完成；扩展会通过 MAIN world 调用 `UE.getEditor(id).setContent()`
- 可打开控制台查看具体失败原因

### 请求失败 / 401 / 404 / 超时

- 检查 Base URL 是否需要 `/v1`
- 检查 Key 是否正确、是否有余额 / 额度
- 返回 `429` / 限流时免费视觉服务会自动退避重试；仍失败可更换模型、Key 或稍后再试

### 图片题没有识别

- 「图片识别」是否开启
- 视觉配置是否有效，可先点「测试识图」
- 主模型不支持视觉时会自动降级为纯文本，日志中会有提示

### 面板没有出现

- 当前页面域名是否受支持
- 扩展是否已启用
- 是否在安装 / 更新后刷新过页面

### 页面脚本能读到我的 API Key 吗？

- **已保存的 Key 不能**：面板是 `closed` Shadow DOM，页面拿不到 `shadowRoot`；Key 不回填到输入框，内容脚本只收到 `hasApiKey: true/false`
- Key 只存在于 `chrome.storage.local` 和 Background 内存中，请求也由 Background 发出
- **输入新 Key 时**：面板会阻止键盘 / 剪贴板事件冒泡，但页面若使用捕获阶段监听仍可能记录按键；建议在可信页面完成配置，或配置后不要在考试页重新输入
- 错误信息会在返回面板前脱敏，避免服务商回显 Key 片段

## 12. 权限与隐私

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存 Base URL、API Key、模型名等设置 |
| `host_permissions: <all_urls>` | 用户可填写任意模型地址；图片跨域抓取也需要该权限 |

- API Key 以**明文**保存在 `chrome.storage.local`，请勿在共用设备上保存
- 题面、图片只会发送到**你自己配置的模型接口**
- 扩展不包含统计、埋点、远程配置，不会向第三方上传数据
- **API Key 不会进入网页 DOM**：面板使用 `closed` Shadow DOM，已保存的 Key 不回显；内容脚本只从 Background 获取不含 Key 的公开设置（`hasApiKey` 标记）
- 面板内会阻止键盘 / 剪贴板事件冒泡，降低页面脚本记录输入的可能；但页面仍可通过捕获阶段监听键盘事件，因此不建议在不可信页面输入敏感 Key
- LLM 请求全部在 Background Service Worker 中发出，并用当前 Key 对错误信息做脱敏

## 15. 关键设计

- **样式与面板隔离**：CSS 通过 `?inline` 导入为字符串，写入 `closed` Shadow DOM；宿主节点 `all: initial` + 固定定位 + 最大 z-index，页面脚本无法读取面板内容。面板内的键盘 / 剪贴板事件会阻止冒泡。
- **Key 隔离**：完整设置（含 Key）只存在于 Background；内容脚本通过 `GET_PUBLIC_SETTINGS` 获得剥离 Key 的公开设置，Key 只能通过 `SET_SECRET` 单向写入，保存后输入框立即清空。
- **iframe 支持**：`all_frames: true`。顶层只渲染一个面板；每个 frame 内运行轻量代理。解析、填涂、交卷都会向子 frame 递归转发，支持「顶层 → cards → work」这类多层嵌套；题目 id 用 `c0:`、`c1:` 前缀逐层路由，前缀与 frame 下标稳定对应。
- **学习通作业页**：自动识别 `.singleQuesId .TiMu` 结构，题干取 `.Zy_TItle .fontLabel`，选项取 `li.before-after`（字母 `.num_option` + 正文 `a.after`），点击 `li` 触发 `addChoice`；填空通过 MAIN world 内容脚本调用 UEditor 的 `window.UE.getEditor(id).setContent()`。
- **策略模式**：`BaseStrategy` 实现通用 DOM 解析与填涂；平台子类只声明选择器，页面改版时单点修改。
- **分页式答题**：`paged` 策略通过 `.questionBox` + `.Topicswitching-div` 识别「一页一题」页面。开始时会读答题卡：从**第一道未答题**开始，不重复处理已答题目；每次切题后等待题干真正变化、选项/输入框渲染完成再填涂，避免在页面加载中间连续点击。切换结果分为 `moved / last / failed`：只有确认到达最后一项才结束，切换失败立即停止且不交卷。页面出现提示弹窗时只关闭「取消 / 我知道了 / 关闭」，绝不点提交；单轮最多处理「题数 + 2」页并设置 15 分钟上限。
- **组合题**：智慧树的 `.questionBox` 可能同时包含组合题父题干和当前子题。解析时取最后一个 `.questionTit` 所在子题块，题号（如 `1.2`）、题型、填空 / 选项都来自当前子题；父题干作为「组合题背景」一起发给模型。导航签名同时包含答题卡当前高亮项，避免 `1.1 → 1.2` 被误判为页面没变化。
- **交卷保护**：只有 `已填 === 总题数` 且 `跳过 = 失败 = 0` 才允许自动交卷；智慧树 / 学习通弹窗若包含「未作答 / 未完成 / 还有 N 题」等警告，不会点击提交，并把警告回传到控制台。学习通的提交确认框会等待 `validate` 请求完成后再判定，最多 6 秒。题目全在 iframe 时顶层页面不会误点自己的「提交」链接。
- **事件模拟**：radio / checkbox 使用原生 `checked` setter + `mousedown/mouseup/click/change`；输入框使用原型 setter + `input/change/blur`，兼容 Vue / React 受控组件。
- **图片题**：解析阶段收集题干 / 选项中的 `img`（兼容懒加载 `data-src`），请求前在当前 frame 内抓取并用 canvas 压缩；跨域失败时由 Background 凭 `<all_urls>` 权限代理抓取。
- **视觉服务**：视觉 Base URL / Key / 模型均可独立填写，逐项留空回退主模型；图片请求在 Background 选择视觉配置，纯文本请求仍走主配置。
- **OCR 模式**：先用视觉模型逐张转写图片（公式 LaTeX、表格 Markdown），把结果拼进题干，再交给答题模型；图片内容不进入答题请求，适合「免费视觉 + 文本模型答题」的组合。视觉模型直接作答模式保留，图片按「题目2 图片1」标注顺序附加。
- **答案容错**：Prompt 强制纯 JSON；解析器容忍代码块、前后废话、`{answers:[...]}` 包裹与 `{id: answer}` 映射。
- **请求代理**：API Key 与 LLM 请求都在 Background 完成，Content Script 只传 prompt。

## 17. 已知限制

- 智慧树选择题选项按 Element UI 的 `label.el-radio` / `label.el-checkbox` 适配；若真实页面选项是其他自定义结构，需要在 `ZhiHuiShu.ts` 的 `selectors.option` 补选择器
- 分页式页面（一页一题）当前是**每题一次模型请求**，题量大时耗时与费用会增加
- 图片单题最多 4 张、单次请求最多 8 张；超出部分会跳过并在日志提示
- OCR 质量取决于视觉模型；复杂公式、手写体、低清截图建议使用更强的视觉模型
- 免费视觉服务通常受并发 / 速率限制（如智谱 `1302` / `1305`），扩展会退避重试，仍失败则本轮跳过 OCR
- OCR 结果缓存在内存中，刷新页面或重载扩展后清空
- API Key 以明文保存在 `chrome.storage.local`，请勿在共用设备上使用
- 模型答案可能出错，扩展不做正确性校验
